CHƯƠNG 1: TỔNG QUAN HỆ THỐNG & ĐẶT VẤN ĐỀ

1.1. Bối cảnh và Tính cấp thiết của đề tài

Trong kỷ nguyên chuyển đổi số giáo dục và đào tạo trực tuyến, việc quản lý ngân hàng câu hỏi và tổ chức thi trắc nghiệm đóng vai trò trọng yếu trong việc đánh giá năng lực người học. Tuy nhiên, các phương pháp truyền thống trên máy chủ đơn lẻ (On-premise) hoặc bảng tính thủ công bộc lộ nhiều hạn chế: tốn kém thời gian, thiếu tính ngẫu nhiên khách quan, khó chia sẻ tài nguyên và chi phí vận hành phần cứng vật lý đắt đỏ nhưng thường xuyên quá tải trong giờ thi cao điểm.

Đề tài "Hệ Thống Quản Lý Ngân Hàng Câu Hỏi & Tạo Đề Thi Trắc Nghiệm Tự Động Trên Nền Tảng Cloud" (Quizgen Cloud) được phát triển nhằm ứng dụng sức mạnh của các dịch vụ Điện toán đám mây (Cloud Computing) giải quyết toàn diện các thách thức trên.

1.2. Mục tiêu nghiên cứu

  • Xây dựng giải pháp Cloud Native có khả năng truy cập mọi lúc, mọi nơi qua giao diện Web hiện đại.
  • Tự động hóa quy trình nạp ngân hàng câu hỏi chuẩn định dạng CSV chỉ trong vài giây.
  • Thuật toán Fisher-Yates xáo trộn câu hỏi ngẫu nhiên tuyệt đối và lưu trữ bền vững trên Cloud Firestore.
  • Đảm bảo an toàn định danh với giao thức Google OAuth 2.0 phi mật khẩu.
  • Tối ưu hóa chi phí vận hành ở mức $0.00 cho giai đoạn thử nghiệm nhờ kiến trúc Serverless & Free Tier.

CHƯƠNG 2: KIẾN TRÚC CLOUD & QUY TRÌNH LUỒNG DỮ LIỆU

2.1. Kiến trúc phân tách 3 tầng (Decoupled Cloud Architecture)

                  ┌──────────────────────────────────────────────────┐
                  │                 NGƯỜI DÙNG / TRÌNH DUYỆT         │
                  └───────────────┬──────────────────────────────────┘
                                  │ HTTPS / TLS 1.3
                                  ▼
     ┌─────────────────────────────────────────────────────────────┐
     │                     TẦNG FRONTEND (Vercel Edge)             │
     │  - React 19 Framework + Vite Bundler                        │
     │  - Client-side CSV Stream Parsing (PapaParse)               │
     │  - Responsive Glassmorphism Dashboard UI                    │
     └───────────────┬─────────────────────────────┬───────────────┘
                     │                             │
    Google Sign-in   │                             │ Gọi REST API (JSON)
    Popup Auth       │                             │
                     ▼                             ▼
┌──────────────────────────────┐ ┌───────────────────────────────────┐
│     FIREBASE AUTHENTICATION  │ │     TẦNG BACKEND (Render / GCP)   │
│ - Google OAuth 2.0 Token     │ │ - Node.js Express Server v5       │
│ - Quản lý phiên đăng nhập    │ │ - Thuật toán Fisher-Yates Shuffle │
└──────────────────────────────┘ │ - Firebase Admin SDK Service      │
                                 └─────────────────┬─────────────────┘
                                                   │
                                                   │ Batch Write & Read
                                                   ▼
                                 ┌───────────────────────────────────┐
                                 │     GOOGLE CLOUD FIRESTORE        │
                                 │  - Collection 'Questions'         │
                                 │  - Collection 'ExamPapers'        │
                                 └───────────────────────────────────┘

2.2. Luồng dữ liệu thời gian thực (Data Pipeline)

  1. Xác thực: Người dùng kích hoạt Google Sign-In ➔ Firebase Authentication cấp Token an toàn.
  2. Streaming Parsing: Người dùng tải lên file CSV ➔ PapaParse đọc luồng dữ liệu ngay trên trình duyệt và cấu trúc thành mảng JSON câu hỏi.
  3. Cloud Batch Ingestion: Gửi dữ liệu tới POST /api/questions/upload ➔ Backend dùng db.batch() nạp 110 câu hỏi vào Firestore trong 1 transaction mạng.
  4. Sinh đề thi ngẫu nhiên: Nhận yêu cầu tạo $N$ câu ➔ Backend truy vấn collection Questions, xáo trộn bằng Fisher-Yates và lưu đề thi vào collection ExamPapers với Document ID duy nhất.
  5. Hiển thị: Frontend nhận đề thi và hiển thị trực quan lên Dashboard.

CHƯƠNG 3: TÍNH NĂNG MVP VÀ MINH CHỨNG VẬN HÀNH (SCREENSHOTS)

3.1. Các tính năng cốt lõi

  • Xác thực Google OAuth 2.0: Đăng nhập nhanh 1 chạm, không lưu mật khẩu thô.
  • Nạp dữ liệu ngân hàng tự động: Hỗ trợ file CSV chuẩn MMLU hàng trăm câu hỏi.
  • Sinh đề thi ngẫu nhiên tùy biến: Lựa chọn số lượng 5 câu, 10 câu, 20 câu... độc lập và công bằng.
  • Lưu trữ đám mây vĩnh viễn: Mọi đề thi được cấp Document ID duy nhất trên Cloud Firestore.

3.2. Mô tả 4 màn hình minh chứng vận hành

  • Màn hình 1 - Authentication Panel: Giao diện phong cách Glassmorphism, nút bấm đăng nhập Google an toàn.
  • Màn hình 2 - Data Ingestion: Thanh tiến trình trực quan: Đang đọc CSV ➔ Đang đẩy lên Cloud API ➔ Đã thêm thành công 110 câu hỏi.
  • Màn hình 3 - Exam Generator: Nhập số lượng câu hỏi, hệ thống trả về đề thi có mã Document ID (ví dụ: VxFFY7BxtWEvd6WMtd41), đánh dấu màu nổi bật cho đáp án đúng.
  • Màn hình 4 - Firebase Console: Minh chứng dữ liệu thời gian thực trong 2 collections Questions và ExamPapers trên Google Cloud.

  • Frontend Web Vitals (Lighthouse): FCP 0.8s (Tốt), LCP 1.2s (Tốt), CLS 0.00 (Hoàn hảo), Bundle gọn nhẹ ~245 KB (gzipped).
  • Giải pháp tối ưu thế hệ mới: Đánh chỉ mục băm ngẫu nhiên random_hash giảm thời gian sinh đề xuống < 200 ms và bộ đệm Redis Cache < 50 ms.

CHƯƠNG 7: ĐÁNH GIÁ AN TOÀN & BẢO MẬT (SECURITY CONSIDERATION)

Hiện trạng an toàn: Google OAuth 2.0 phi mật khẩu, HTTPS TLS 1.3 mã hóa toàn trình, quản lý khóa bí mật qua .gitignore và biến môi trường FIREBASE_SERVICE_ACCOUNT, kiểm soát nguồn gốc CORS.

Lộ trình nâng cấp 4 lớp cho bản thương mại:

  1. Phân quyền vai trò RBAC bằng Firebase Custom Claims (Teacher, Admin, Student).
  2. Xây dựng Middleware authenticateToken kiểm tra chữ ký số JWT Google trên Express.
  3. Thiết lập bộ quy tắc Firestore Security Rules khóa quyền truy cập database trực tiếp từ client.
  4. Áp dụng express-rate-limit chống tấn công Flood Request / DoS (giới hạn 30 req/15 phút).
